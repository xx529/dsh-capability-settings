## 1. 设计原则

1. **一个动作一个控件**：批量动作（全部开启 / 全部关闭）与会话级开关同层；单条开关在卡片 / 行尾。
2. **会话态 ≠ 项目默认**：批量与派生设置只作用于当前会话，不提供改项目默认的捷径。
3. **无二次确认**：全部开启 / 全部关闭都一步生效（可逆、可观察计数与卡片状态），不设确认条 / 模态。
4. **三域整体**：全局开关与派生继承都按 `Skills · MCP · Tools` **整体**作用，不做按模块的分别开关。
5. **来源一致**：插件 / 内置 / 预设 / 项目 / 全局在同一套标签形状与配色下呈现（列表、详情、会话首屏一致）。
6. **密度上限**：hero 容器内宽 920px（任务书的 ~936 为含边距近似值）；新增控件不得把第三域 Tab 或
   「管理全部 / 能力决策」挤出可视区，不允许文字截断。

### 2.3 三域模型

| 域 | Tab 文案 | Tab 计数语义 | 开关粒度 |
|---|---|---|---|
| Skills | `Skills` | 已启用 / 全部条数（`8 / 15`） | 单条 skill（会话级） |

| Tools | `Tools` | 已启用插件 / 全部插件（`3 / 6`） | **整插件**（一个插件 = 一个可开关单元；无单工具开关） |

### 2.4 域边界（MCP vs Tools，v1.8 新增）

- **MCP 域**收录：① 配置文件 MCP（mcp-client 实例，`~/.agents/mcp.json` / 项目 `.mcp.json`）；
  ② **插件自注册的 `mcp__<server>__*` 命名空间**（如 dsh-to-figma 的 `mcp__figma__*`，无 mcp-client 实例，需合成来源行）。
- **Tools 域**只收录：**插件直接注册、且非 `mcp__` 前缀**的工具（如 `univer_*`、`rw_*`、`dsh_im_*`、`sidebar_open`、
  `open_in_popout`、`dsh-diff-approval-annotate`）。
- 两域**互斥、不重复收录**：插件注册了 MCP 就归 MCP 模块管理；Tools 不出现 `mcp__*` 行（例外：MCP 域合成行只出现在 02 / MCP 列表）。

### 2.5 能力面板（`main` 整页）

- Tab 行：`Skills` / `MCP` / `Tools` / `Jev 模型`（顺序固定；`Jev 模型` 保留入口、非 Tools 页不高亮）。
- Tools 页**两栏**：中间 = 插件行列表，右侧 = 插件详情；**不显示左导航**（Tools 全局注册、无 scope / 工作区维度）。
- header 文案：`全局工具注册 · 不区分项目 / 工作区`，右侧下拉 `全局工具 ▾`。

## 3. R1 · 全局一键开启 / 关闭

### 3.1 控件

| 元素 | 规格 |
|---|---|
| 位置 | 行 3 左端：`全部开启` 64×24、`全部关闭` 64×24（间距 6），其后 12px 计数 |
| 文案（精确） | `全部开启` / `全部关闭`；执行中 `全部开启中…` / `全部关闭中…` |
| 样式 | `全部开启`：蓝 `#61AFEF` 12% 底 + 蓝 35% 描边 + `#8FBCFF` 字；`全部关闭`：白 14% 描边 + `#C9CED8` 字；禁用：白 4% 底 + white 8% 描边 + `#5E6673` 字 |
| 计数 | `已启用 16 / 30`（示例；规则见 §3.6） |
| 范围说明 | 计数后固定弱文案：`仅当前会话 · 不改项目默认` |
| tooltip | `作用于本会话的 Skills · MCP · Tools 三域整体`（不做按模块的分别开关） |

### 3.2 作用范围

- 作用于**当前会话的三域**：Skills（会话 shadow）、MCP（会话 restrict / remount）、Tools（按插件 restrict 该插件全部工具）。
- **不修改**项目默认（`capability-overrides.json`）、全局配置或其他会话。
- **不包含**：宿主内置基础工具（read / write / bash / glob / grep / web_search / skill / todo_write / present /
  subagent / spawn_teammate / workflow / ralph 等）——它们不是插件注入项，且注册在 agent 自身层，
  `tools.restrict` 契约只能过滤继承层、关不掉。
- 一键开启 = 把三域**可关闭单元**全部打开；不可 restrict 的 MCP / 插件保持只读或置灰，不参与。

### 3.3 状态矩阵

| # | 状态 | 全部开启 | 全部关闭 | 行 3 计数 | 其他 |
|---|---|---|---|---|---|
| S1 | 三域全开（30/30） | **禁用** | 可用 | `30 / 30` | 无 |
| S2 | 部分开启（默认态） | 可用 | 可用 | `16 / 30` | 无 |
| S3 | 三域全关（0/30） | 可用 | **禁用** | `0 / 30` | 卡片全灰；无提醒条（见 §3.4） |
| S4 | 执行中（逐条 RPC） | 禁用，`全部开启中…` | 同理 | 追加 `正在关闭 87 / 156…` | 行开关置灰防抖；输入不阻塞；乐观回显 |
| S5 | 部分失败 | 可用（重试剩余） | 可用 | `3 项失败 · 重试`（红字） | 失败项保持原状态；不弹模态 |
| S6 | 加载中（无快照） | 禁用 | 禁用 | `—` | 行开关置灰 |

- 按钮在目标态时**禁用而不隐藏**；`aria-disabled="true"`，tooltip `已全部开启` / `已全部关闭`。
- **无二次确认、无提醒条**：不设确认条 / 模态 / 倒计时 / 警告条 / 快捷按钮；全部关闭直接生效，用户通过控制条的「全部开启」按钮恢复。

### 3.4 关闭后的空态（帧 04）

- 行 3：`已启用 0 / 30`；`全部开启` 可用（蓝描边强调）、`全部关闭` 禁用。
- **不设提醒条 / 快捷按钮**（用户第五轮明确删除）：网格上方无任何横幅，只有 4 列卡片全灰；恢复入口就是行 3 的「全部开启」。
- 三域卡片全部关闭态：底色 `#1B1F27`、无描边、开关灰、名称 `#9DA5B4`。
- 底栏：`0 / 30 项已启用 · 开关只作用于当前对话`。
- 该状态在规格中定义并由 tester 走查；Figma 帧 04 即画此状态。

### 3.5 计数口径（规则）

1. **Tab 计数** = `已启用 / 全部`，按域：Skills `8/15`、MCP `5/9`、Tools `3/6`。
2. **控制条 / 底栏计数** = 三域已启用数相加 / 总可开关单元相加：`16 / 30`；全关帧 `0 / 30`。
3. **Tools 的单元是插件**：卡片描述显示插件内工具数（17 / 13 / 19 / 8…），Tab 分母是插件数（6）。
4. **未展示单元按 0 启用计入分母**：hero 目前展示全部 6 个 Tools 插件；若后续出现未展示插件，按 0 启用计入。
5. **示例标注**：真实枚举随插件安装变化、宿主无权威映射；图注 / 帧注统一写「计数为示例口径，以运行时枚举为准」。

### 3.6 底栏

- `16 / 30 项已启用 · 其中 4 项来自插件 / DSH 内置 / Agent 预设 · 开关只作用于当前对话`。
- 全关帧：`0 / 30 项已启用 · 开关只作用于当前对话`。

## 4. R2 · 派生继承（布尔，无分型；**本版未实现 · 零渲染**）

> **实现状态（验收口径）**：本节及帧 01–05 的派生继承控件均为**设计提案**，本版代码不渲染、不落存储、无 RPC。
> 验收时按「UI 无派生继承控件」为通过；不要据此判为缺陷。以下内容保留供后续 phase 参考。

### 4.1 裁决

- 首屏行 3 右侧只有：`派生继承` 标签 + 分段控件 **`继承` | `不继承`**（70×18，轨道 146×24，选中蓝底）；
  不再有 `分型策略…` 链接、弹层或第三态（用户第 7 轮明确删除）。
- 语义：**subagent 与 teammate 共用同一个开关**，**整体**作用于 `Skills · MCP · Tools` 三域，**不按模块分**。
- 默认值：`继承`（提案 §3.2 的 `inherit`）。
- 首屏弱提示：`派生 agent 整体继承三域`（位于分段控件左侧；920 内单行不换行）。
- tooltip：`作用于 subagent / teammate 的 Skills · MCP · Tools 三域整体`。

### 4.2 状态与文案

| 状态 | 分段控件 | 说明 |
|---|---|---|
| 继承（默认） | `继承` 选中 | `派生 agent 继承本会话的 Skills · MCP · Tools` |
| 不继承 | `不继承` 选中 | `派生 agent 按项目默认配置`（= 旧行为） |
| 运行中已有 child | 同常态 | toast：`已创建的派生 agent 不受影响，新派生的才生效` |

### 4.3 边界（必须防的隐形回归）

1. **只影响之后的派生**：改开关只对之后 spawn 的 child 生效；已 live 的 child 不因策略变化被重算（toast 说明）。
2. **接收者范围**：`inherit` 的基线是**直接父 agent** 的生效集合（提案 §3.3），UI 不承诺「一定等于本会话」。
3. **与能力决策兼容**：Jev 自动选择只收窄，永不扩权；父级已关闭的能力不会被恢复。
4. **失败降级**：策略读写失败 → 控件回上次快照 + 行内错误 `派生策略保存失败，请重试`（不弹模态；本版无弹层）。

### 4.4 实现状态（避免把提案当已实现）

- R2 目前是**提案 + 零代码**（无 lineage / 无 policy 字段 / 无 RPC）；本版 UI 先出，实现属提案 phase 1。
- **默认「继承」会改变现有行为**：子 agent 从「按项目默认全开」变为「跟随父会话生效集合」；上线需在 README /
  CHANGELOG 明示，并提供一键「不继承」回退旧行为。
- 与关工具正交：关掉 `subagent` / `spawn_teammate` 不影响继承机制，但会让该 agent 无法派生（工具 tooltip 说明即可）。

| 无任何 Tools 项 | `尚未发现 Tools` + 副文案 `安装注册了直接工具的插件后，这里会列出对应插件` |
| 无法枚举（宿主 tools 视图不可用 / 读取失败） | `无法列出 Tools` + `重试` 链接（行内错误，不弹模态） |
| 搜索无结果 | `没有匹配的插件或工具` + `清空搜索` |

- 统一使用 `Tools` 词汇；**不得**再出现「插件工具」空态文案（与 §2.1 命名禁令一致）。

### 5.5 归属启发式（E1）与降级

- 宿主 `tools.schemas()` 只有 name / description / parameters，**无来源字段**。插件归属靠旁路映射：
  `univer_*`→dsh-univer-office、`rw_*`→dsh-remote、`dsh_im_*`→@xmanrui/dsh-im、`sidebar_open`→dsh-better-sidebar、
  `open_in_popout`→dsh-popout-window、`dsh-diff-approval-annotate`→dsh-diff-approval。
- **`mcp__<server>__*` 不进入 Tools**：按 §2.4 域边界归 MCP（插件自注册的 MCP 命名空间走 MCP 域的合成来源行，见 §6）。
- **识别不到 → 归入 `来源未识别` 分组（`未识别` 琥珀标签），不猜成宿主内置**。
- 若某插件无法 restrict（注册在 agent 自身层）：开关禁用（40% 灰）+ 原因 tooltip `该插件无法按会话关闭`，不参与批量；
  本版不提供单工具只读行（避免把 Tools 做成全量工具列表）。

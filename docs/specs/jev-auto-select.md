凡是本规格提到「宿主」「一次请求」「脱敏」的地方，都只描述**对外可观察的产品语义**。

## 1. 背景、现状与目标

### 1.1 用户原始需求（逐条，v1.3 口径）

1. 在能力面板新增配置 Jev 模型的 Tab：输入 base URL 和 key（或指定环境变量）；同一 Tab 内还可配置「能力决策」区（自动触发开关、停顿阈值、最少触发字数、最少修改间隔字符数）。
2. 对话开始首页新增「✦ 能力决策」：**自动触发默认关闭**，开启后用户在新会话输入框输入并停止输入达到停顿阈值（默认 1.0 秒，可配置 300–3000ms）、草稿字数达到「最少触发字数」（默认 10）、且自上次决策以来编辑字符数达到「最少修改间隔字符数」（默认 4）时，自动发起一次评分，无需点击；手动按钮始终可立即触发。评分按分数排序，可选择阈值以上能力应用。
3. 不允许每个技能 / MCP 各发一次 Jev 请求，必须**一次请求同时多个**（参考 Jev 最佳实践）；**固定一次请求，不做分片**，超出上下文时进入「内容过长」错误态。
4. 先出 Figma 交互原型并经用户确认后再开发。

> 历史：v1.0 用户口径为「点击按钮触发」；v1.2 改为「输入停顿自动触发」；v1.3 统一命名「能力决策」、自动触发默认关闭、新增字数 / 修改量门槛。旧称与历次口径见 §10 变更记录。

### 1.3 目标（本期做什么）

| 编号 | 目标 |
|---|---|
| G1 | 用户可以在能力面板「Jev 模型」Tab 完成一次性配置（Base URL / API Key 或环境变量 / 模型名），配置**全局生效**、保存后无需重启，密钥不以明文下发浏览器 |
| G2 | 用户在**对话开始首屏**输入草稿后，开启自动触发时，**停顿达阈值（默认 1.0s，可配 300–3000ms）且草稿字数 ≥ 最少触发字数（默认 10）、自上次决策编辑字符数 ≥ 最少修改间隔字符数（默认 4）即自动发起一次评分**（无需点击）；未开启或门槛不满足时，可点「✦ 能力决策」立即触发。一次请求给当前会话全部可评分能力各打一个 0–1 分 |
| G3 | 结果按分数降序展示；用户可用阈值滑杆（默认 0.50、步长 0.05）批量预勾选，也可逐项手改勾选；调整阈值**不重新请求** |
| G4 | 用户点击「应用所选」后，只修改**当前会话**的能力开关；成功后收起结果面板，能力条 chips 回显已启用能力；失败可感知、可重试、不留下半套状态 |
| G5 | 未配置、草稿为空、等待停顿、自动触发中、自动触发已取消、自动触发关闭（默认）、草稿字数不足、编辑量不足（缓冲期）、评分中、无匹配、内容过长、网络/鉴权错误、部分能力不可切换等全部状态都有明确中文文案与下一步动作 |
| G6 | 本规格可直接驱动 ux 出 Figma 原型、tester 写验收；验收标准逐条可观察 |
| G7 | 配置 Tab 的「能力决策」区可开关「输入停顿后自动评分」（默认关）、调整停顿阈值（默认 1000ms，300–3000ms、步长 100ms）、最少触发字数（默认 10，1–200）、最少修改间隔字符数（默认 4，1–100）；关闭后不自动触发，手动按钮仍可用；保存后立即生效 |

### 1.4 非目标（本期明确不做）

| 编号 | 不做 |
|---|---|
| N1 | 不自动执行 / 调用任何能力，不自动发送消息，不做 agent 编排 |
| N2 | 不做长期学习、记忆、历史会话分析或跨会话偏好；评分只基于**当前输入框草稿** |
| N3 | 不做云端同步、多用户共享、团队配置；配置只在本机宿主全局 |
| N4 | 不做每个能力一次请求；不允许「先列 TOP-N 再评分」的两段式请求（一次运行必须覆盖全部参与评分的能力）；**不做自动分片**（单次请求装不下即失败，见 §5.4） |
| N5 | 不做 MCP 工具级评分与工具级开关（本期 MCP 以服务器为粒度；工具级是否入参见 §8 O-4） |
| N6 | 不做自动应用、自动重评分、评分结果缓存或离线；但「应用所选」按筛选语义会**在当前会话关闭未勾选的可应用能力**（见 §5.9） |
| N7 | 不修改项目默认（不写 `.agents` 的默认声明、不改 MCP 行尾「默认」开关、不改技能落盘 frontmatter） |
| N8 | 不在会话进行中（active 相位）提供能力决策入口或自动触发；不改造会话内顶部「能力」Tab |
| N9 | 不新增评分理由/自然语言解释展示（Jev 输出结构化判断，不做生成式解释）；不做多语言 UI |
| N10 | 不改变现有「技能 / MCP」两个 Tab 的行为与 IA（除新增第三个 Tab 所需的头部调整） |
| N11 | 不做输入停顿的悬浮倒计时浮层、声音提醒或桌面通知；等待状态只在能力条 / 面板内以弱提示表达 |
| N12 | 不做自动重试与自动重新评分；自动触发受「最少修改间隔字符数」约束，未达到最少修改量不会再次自动触发；失败后需用户手动重试 |

### 1.5 体验目标（可观察，不做 KPI 承诺）

| # | 目标 | 观察方式 |
|---|---|---|
| UX-1 | 首次使用：从首屏触发到完成配置并返回 ≤ 6 次点击（不含文本输入） | 原型走查 / 真机点击计数 |
| UX-2 | 日常使用：手动触发「✦ 能力决策」→「应用所选」= 2 次点击；开启自动触发后停笔 1.0s 出结果 → 1 次点击（自动触发不计点击） | 同上 |
| UX-3 | 阈值调整与手改勾选不产生任何评分请求 | 假 Jev 端点请求计数 |
| UX-4 | 任何一个错误态都给出「下一步做什么」，不出现只有英文栈或死胡同的状态 | 状态走查清单（§5.10） |
| UX-5 | 自动触发不打断输入：等待与评分期间输入框始终可继续输入，不抢焦点、不弹 toast | 原型走查 / 真机输入 |
| UX-6 | 默认零打扰：自动触发默认关闭时，不产生任何后台请求、不显示倒计时；仅手动触发才请求 | 假端点请求计数 / 状态走查 |

### 3.1 两个面、一个入口（手动 + 自动）

```
首屏对话（hero，输入框正下方「本会话能力」）
├─ 展开态面板头部：本会话能力 ····· [✦ 能力决策] [搜索] [收起]
├─ 收起态能力条： 本会话能力 · chips ····· 计数 · [✦ 能力决策] [配置]
├─ 自动触发已开启 + 停顿 ≥ 停顿阈值 + 字数/修改量达标 → 自动展开并进入「评分中」（无需点击）
└─ 点击「✦ 能力决策」→ 立即在同一位置切换为「结果面板」（hero fixed 容器内）
```

- 配置面与能力决策面**不在同一屏**：配置在能力面板主区域；能力决策在首屏。
- 扫读优先级：结果面板先行（用户此刻要“选能力”），配置是冷路径（只有未配置 / 出错才去）。
- 自动触发与手动触发**共用同一结果面板与同一套状态**；自动触发只是「不需要点击」的入口。
- 停顿时只做计时与门槛检查，不改输入框内容、不抢焦点、不弹 toast（见 §5.1、§5.2、§5.8）。
- 自动触发**默认关闭**：首次使用不产生任何自动请求；入口显示「自动触发默认关闭 · 可在 Jev 模型 Tab 开启」提示。

补充规则：

- 保存成功后 **API Key 输入框清空**，并切换为 `已保存 · 尾号 {last4}` + `更换`。

- 保存时若 API Key 输入框为空且此前已有保存密钥 → **保持原密钥不变**（允许只改 Base URL / 模型名）。
- 保存时若 API Key 输入框为空且此前无保存密钥（且未开环境变量模式）→ 阻止保存，行内错误「请填写 API Key，或切换到「环境变量」」。

- 表单字段的输入不做实时网络请求；只有 `测试连接` 与 `保存` 会触达宿主 / Jev。

### 4.2 两种密钥模式与切换语义

| 场景 | 产品语义 |
|---|---|
| 模式 A：直接填写 API Key | 密钥由宿主保存在 `~/.dsh/capability-panel/jev.json`（目录 700 / 文件 600；`DSH_HOME` 存在时以 `$DSH_HOME` 为根）；评分 / 测试时由宿主读取并使用；浏览器不再获得已保存密钥明文 |
| 模式 B：环境变量（密钥来源 = 「环境变量」） | 配置只保存**变量名**；评分 / 测试时由宿主从自身进程环境读取该变量的值；浏览器既不保存也不展示变量值 |
| A → B（保存后） | 已保存的直接填写的密钥在宿主侧清除；配置进入模式 B；此后评分只读环境变量 |
| B → A（保存后） | 环境变量名保留但不生效；必须填写 API Key 才能保存成功（空则阻止并提示） |
| 未保存的切换 | 仅改变表单显示，不改变已保存配置；离开页面即丢弃 |
| 环境变量值缺失 | 保存本身允许（配置完整），但 `测试连接` 与评分会失败并给出「宿主环境变量 X 未设置」；不静默回退到其它模式 |
| 已保存密钥的可见性 | 任何界面、接口响应、DOM 中都不得出现已保存密钥的明文；直接填写模式只展示 `已保存 · 尾号 {last4}`，环境变量模式只展示来源「环境变量」与变量名 `{name}`，均不展示变量值 |
| 落盘与权限 | 直接填写的密钥只落在 `~/.dsh/capability-panel/jev.json`（目录 700 / 文件 600；`DSH_HOME` 存在时以其为根）；浏览器 LocalStorage / SessionStorage / IndexedDB / DOM 中不出现密钥明文 |

### 4.4 保存与生效

- 保存成功后：写入**全局配置**，并显示轻提示 `Jev 配置已保存`；表单切换为「已保存」展示（密钥脱敏）。
- 保存成功后**不自动关闭配置页、不自动跳回首屏**：保持当前 Tab 与滚动位置，仅把表单刷新为已保存状态（用户自行返回）。
- **保存后无需重启宿主、无需刷新页面**：下一次评分 / 测试使用新配置。已打开的评分结果面板不因保存而变化（需要重新评分才使用新配置）。
- 保存成功后「能力决策」开关、停顿阈值、最少触发字数、最少修改间隔字符数立即生效：下一次草稿变化 / 停顿即按新值判定，无需重启或刷新。
- 保存失败：保留用户输入，页面顶部/动作区下方显示错误条 `保存失败：<原因>` + `重试`；表单不清空。
- 保存成功时如果有未保存的「环境变量模式」切换，以保存后的模式为准。
- 配置作用域：**全局，所有项目 / 所有会话共享**；页面上必须常驻一句 `全局配置 · 所有项目和会话共享`。
- 保存成功后回到会话首屏：`✦ 能力决策` 按钮下次读取配置时反映最新状态（不再显示“去配置”蓝点）；若能力决策此前关闭，按钮仍可手动触发。

## 5. 能力决策面规格

### 5.1 入口状态与触发条件（手动 + 自动）

**触发方式（v1.3）**

| 方式 | 前置条件 | 结果 |
|---|---|---|
| 自动触发（默认关闭） | hero 相位 + 配置「输入停顿后自动评分」= **开**（默认关）+ Jev 已配置 + 草稿字符数 ≥「最少触发字数」（默认 10）+ 自上次能力决策以来编辑字符数 ≥「最少修改间隔字符数」（默认 4）+ 当前无评分进行中 / 无应用进行中 + 未处于「自动触发静默」 | 停顿达到「停顿阈值」（默认 1000ms，可配 300–3000ms）后**自动展开结果面板并进入评分中态**；不弹 toast、不抢输入焦点。**默认关闭时不发生** |
| 手动触发 | 按钮状态为「可点」（见下表优先级 10） | 点击后立即发起一次评分（不等停顿，也不受自动触发开关 / 字数 / 修改量门槛限制；草稿非空即可） |

**按钮状态的判定优先级（从高到低，命中即停止）**

| 优先级 | 条件 | 按钮表现 | 点击行为 | tooltip / 辅助文案 |
|---|---|---|---|---|
| 1 | 正在评分（本面板发起且未结束） | 文案 `评分中…`，禁用 | 无 | `正在评分，请稍候` |
| 2 | 正在执行“应用中” | 禁用 | 无 | `正在应用所选能力` |
| 3 | Jev 配置读取失败（已确认） | 可点 | 打开结果面板的 `config-error` 态 | `读取 Jev 配置失败，点击查看详情` |
| 4 | Jev 未配置 / 鉴权不完整（已确认） | **可点，右上角 4px 蓝点** | 打开能力面板并选中 `Jev 模型` Tab（保留“去配置”提示条） | `尚未配置 Jev 模型，点击去配置` |
| 5 | 能力列表或配置仍在加载 | 禁用 | 无 | `正在加载本会话能力…` / `正在读取 Jev 配置…` |
| 6 | 可评分能力数 = 0 | 禁用 | 无 | `当前会话没有可评分的技能或 MCP 服务器` |
| 7 | 可切换能力数 = 0（全部不可切换） | 禁用 | 无 | `当前会话没有可切换的能力` |
| 8 | 草稿为空（见 §5.2） | 禁用 | 无 | `先在输入框写下你要做的事` |
| 9 | 草稿读取不可用（旧外壳且 DOM 兜底也失败） | 禁用 | 无 | `无法读取输入框内容` |
| 10 | 其余（已配置 + 有草稿 + 有可切换能力） | 可点 | 触发一次评分 | `根据输入框草稿，为技能和 MCP 打分并勾选相关能力（仅当前会话）` |

补充：

- 「未配置」**不禁用按钮**：用 4px 蓝点 + tooltip 引导，点击去配置；即使草稿为空也优先执行“去配置”。
- **自动触发默认关闭**：未在配置中开启时，不武装停顿计时、不产生任何自动请求；入口显示弱提示 `自动触发默认关闭 · 可在 Jev 模型 Tab 开启`。
- 自动触发只在按钮处于优先级 10 且配置开关开启时武装；其它优先级下不武装停顿计时，也不弹任何提示。
- 停顿计时中按钮保持可点：点击 = 立即触发，同时取消计时（不会产生第二次运行）。
- 评分失败后的按钮回到可点状态（重试可直接再点）；自动触发失败**不自动重试**。
- 禁用状态必须可被读屏感知（`aria-disabled` + 说明），不能只靠变灰。
- 按钮不能出现“看起来可点但无反应”的状态：凡是禁用都必须在 tooltip 里给原因。
- **自动触发两个门槛**（同时满足才武装）：①草稿字符数 ≥「最少触发字数」；②自上次能力决策（自动或手动）以来累计编辑字符数（插入 + 删除）≥「最少修改间隔字符数」。
- 自动触发被取消后，同一草稿进入静默（约 3s 弱提示）；需再累计编辑 ≥「最少修改间隔字符数」并停顿达标才可能再次自动触发（见 §5.8）。
- 手动触发不改变「最少修改间隔字符数」的累计规则以外的状态：仍按 §5.2 在触发时把编辑计数与基线重置为 0。
- 自动触发不弹 toast；等待与取消状态只在能力条 / 面板内以弱提示表达（§5.14）。


### 5.2 草稿的定义、读取、停顿计时与编辑计数

| 项 | 规格 |
|---|---|
| 草稿来源 | 当前对话输入卡的**未发送文本**（首屏所见即所得）。只读当前值，不读历史消息、不读已发送内容 |
| “为空”判定 | 去除首尾空白（含全角空格、换行）后为空 → 视为空；纯空白、只有换行都算空 |
| 草稿字符数 | 去除首尾空白后的 **Unicode 码点数**（中文 / 英文 / 数字 / 符号各计 1；emoji 按码点计，组合 emoji 可能 > 1）。与「为空」判定使用同一份 trim 语义 |
| 草稿字符数门槛 | 草稿字符数 ≥「最少触发字数」（默认 10，范围 1–200）才可能自动触发；不足时不显示倒计时、不发送请求（手动按钮只要求非空，不受此门槛限制） |
| 编辑字符数定义 | 自上次重置点以来累计的**插入字符数 + 删除字符数**（均按 Unicode 码点计）。单次草稿变化用「最长公共前缀 / 最长公共后缀」对齐：前缀与后缀之外的新增部分计为插入、缺失部分计为删除；替换视为「删除旧字符 + 插入新字符」；仅增删首尾空白不计入 |
| 编辑字符数重置点 | ①任意一次能力决策触发（自动或手动，成功发起评分即重置）；②草稿被清空；③发送首条消息（进入 active 相位、hero 卸载）。重置后从 0 重新累计；保存配置、切换 Tab、开关自动触发都不重置 |
| 修改量门槛 | 编辑字符数 ≥「最少修改间隔字符数」（默认 4，范围 1–100）才允许再次自动触发；未达标时不显示倒计时（缓冲期），继续输入会继续累计 |
| 门槛与停顿计时的关系 | 每次草稿变化都**重置停顿计时**，但**不清零编辑字符数**；停顿到点那一刻同时校验「草稿字符数门槛」与「修改量门槛」，均满足才发起自动评分 |
| 附件 / 图片 | 本期只看文本：有附件但无文本时视为空（按钮禁用、自动触发不武装）；多模态草稿为后续版本议题（本期不做） |
| 草稿清洗 | 只发送用户可见文本：去除零宽字符与内部 chip 占位符（如 `U+E100–U+E11D`、`U+FFFC`）；技能 chip 能取到可读名称则替换为名称，取不到则移除；`/name` 等用户输入文本原样保留；**不把占位符原样发给 Jev** |
| 草稿变化事件 | 文本 trim 后内容发生变化（键入、粘贴、删除、清空、撤销）才算一次变化：**重置停顿计时并累计编辑字符数**；仅增删首尾空白视为无变化（不计编辑字符数）。输入法组合（composition）期间不触发，`compositionend` 后开始计时并计入编辑字符数 |
| 停顿计时 | 以最后一次草稿变化事件为起点；达到「停顿阈值」（配置值，默认 1000ms）后先校验两个门槛，满足才触发自动评分；计时期间任何新输入都重置。不使用轮询，不抢焦点、不写输入框 |
| 读取通道（首选） | 宿主槽 standardProps 的 `useInput` / `input.draft`；同时订阅其变化驱动停顿计时与编辑计数 |
| 读取通道（降级） | 旧外壳没有 `useInput` 时：DOM 读取 Lexical contenteditable 文本 + 清洗 chip 占位符，并订阅 DOM 输入事件驱动停顿计时与编辑计数；两种方式都失败 → 入口保留但禁用 + tooltip `无法读取输入框内容`（见 O-6） |
| 快照时机 | 手动点击或自动触发到点的瞬间取一次草稿快照；本次评分只使用该快照；评分过程中修改草稿不会自动重发 |
| 草稿变化（结果期间） | 已出结果不随草稿变化而改写（仍基于上次快照，可继续应用）；修改草稿后可点 `重新评分` 用最新草稿重评；若草稿被清空，`重新评分` 禁用并提示 `输入框已清空`。若自动触发开启且字数 / 修改量门槛满足，停顿到点后自动以新草稿发起评分并替换为评分中态（UX v1.5 §7.1 S19） |
| 草稿变化（等待 / 评分期间） | 评分期间的草稿变化不打断本次请求，但会继续累计编辑字符数（自本次触发后从 0 起）；评分结束后若草稿字数与编辑量达标，停顿计时可重新武装 |
| `重新评分` | 始终使用点击 `重新评分` 时的最新草稿；若草稿为空则禁用并给出原因 |
| 超长草稿 | 若单次请求上下文无法容纳「草稿 + 全部能力」→ 评分失败并提示内容过长（见 §5.4、§5.11）；**不自动截断、不分片** |
| 草稿隐私 | 草稿只发送给用户配置的 Jev 服务；不写入本地日志、不落盘（评分结果内存态）；停顿计时与编辑计数只在浏览器内存中进行 |


### 5.3 可评分能力集合（纳入 / 排除口径）

**产品口径：一个评分运行必须覆盖“当前会话能力面板里用户能看到的全部能力”，每个能力恰好一个分数。**

纳入规则（与首屏「本会话能力」现有展示范围一致）：

| 类型 | 纳入条件 | 展示标识 |
|---|---|---|
| 技能 | 当前会话能力列表中的技能，按名称去重（同名只保留宿主当前生效的那一份，通常是项目副本） | 徽标 `技能` |
| MCP | 当前会话能力列表中的项目条目（含引用 / 导入）、全局已启用条目 | 徽标 `MCP` |
| MCP | 运行时外部注入实例（只读展示） | 徽标 `MCP` |

排除规则（**不进入评分**，也不会出现在结果列表）：

| 排除项 | 原因 |
|---|---|
| 项目内屏蔽占位（shadow stub） | 不是真实能力（现有会话面板也不展示） |
| 文件级双向禁用的技能（模型与用户都不可调用） | 现有会话列表已过滤；会话内无法启用，评分无行动价值 |
| 配置中 `enabled=false` 的 MCP 条目 | 当前无法生效 |
| 被项目同名条目遮蔽的全局 MCP | 当前项目中不生效（会话面板只列生效条目） |
| 名称 / 描述均为空的能力 | 无评分输入 |

不可切换（**仍参与评分、仍显示分数，但勾选禁用、不计入“可切换”计数**）：

| 分类 | 判定（产品语义） | 结果行标识 / 原因文案 |
|---|---|---|
| 技能：会话未激活 | 当前会话还不能写会话开关（例如冷会话 / 无 live agent） | 勾选框禁用 + 原因 `会话未激活` |
| MCP：外部注入且不可按会话控制 | 宿主约定该实例无法在当前对话屏蔽 / 恢复 | 勾选框禁用（展示为已启用）+ 原因 `不可在当前对话关闭` |
| 其它宿主明确返回不可切换的能力 | 以宿主返回为准 | 勾选框禁用 + 宿主原因文案；无原因时 `当前会话无法切换该能力` |

数量定义（结果面板与入口使用）：

- `N` = 参与评分的能力总数（结果行数；**含不可切换项**）。
- `K` = 不可切换能力数（N 的子集）。
- `M` = 可切换能力数 = `N − K`；只有 M 中的能力可以被勾选 / 应用。
- **对外计数统一单基数**：结果面板阈值行显示 `已选 {n} / {N}`；`M` 只用于入口可用性判定（M = 0 时禁用入口）与应用对象，**不作为分母展示**。
- 若 `M = 0`：入口按钮禁用（§5.1 优先级 7），不发起评分。

**结果行不展示作用域标签**（项目 / 全局 / 外部）：v1.2 裁决为 P2，本期不展示（UX v1.5 §6.6 亦标注为可选 P2，未进入必保清单）；作用域仍用于应用语义判定。

### 5.4 一次批量请求的产品语义（固定一次请求，不分片）

**核心约束（用户需求 3）**：一次评分运行**不允许**为每个技能 / MCP 各发一次 Jev 请求，也**不做自动分片**。

| 项 | 规格 |
|---|---|
| 基本语义 | 一次评分运行 = **恰好 1 次**对 Jev 的评分请求，覆盖全部可评分能力（N 个）；请求一次返回每个能力恰好一个 0–1 分 |
| 固定一次请求 | 请求次数恒为 1，与能力数无关；不存在分片、分批、多轮；加载态状态行固定显示 `1 次请求`（结果态无说明行） |
| 分数容错（F1 裁决） | 每个能力仍对应一个分数，但宿主按容错解析：数值 **clamp 到 [0,1]**（如 `1.2`→`1`、`-0.2`→`0`）；布尔 `true`→`1` / `false`→`0`；`{value:number}` 取 value；**缺失 / 字符串 / `null` / `NaN` / 不可解析 → 该能力 `score=0` 且 `reason="no-answer"`**，不丢弃该能力、**不整单失败**；结果行显示「未获得评分」弱提示（可解释，不阻塞勾选与应用） |
| 超出上下文 | 若「草稿 + 全部能力资料」超出单次请求上下文预算 → **不拆分、不截断、不丢弃能力**，评分失败进入「内容过长」错误态（`context`，见 §5.11），提示用户缩短草稿后重试 |
| 请求内容 | 用户输入框草稿 + 每个能力的一句话资料（技能名称与描述；MCP 名称与摘要）。**不发送**历史对话、文件内容、项目路径、密钥 |
| 请求发起方 | 评分请求由**宿主**发起，浏览器不直接访问 Jev 服务；浏览器网络面板中看不到对 Jev 的请求 |
| 可观察证据（验收用） | 用可配置的「假 Jev 端点」记录请求次数与请求体：①任意能力数（8 / 37）→ 恰好 1 次请求；②构造超出上下文的夹具 → 仍只有 1 次请求，随后进入「内容过长」错误态；③请求体包含草稿与全部 N 个能力资料；④请求体不含历史消息、文件正文、密钥 |
| 重试语义 | 只有用户显式点击「重试 / 重新评分」或新的停顿自动触发（草稿已变化）才会再次发起；宿主对 429/529 的传输层重试不改变可见状态（加载态仍显示 `1 次请求`），且不得出现按能力拆分请求 |

### 5.5 加载态

| 区域 | 表现 |
|---|---|
| 进入方式 | 手动点击后立即进入；自动触发时面板**自动展开并直接进入本态**（无需点击、不弹 toast） |
| 头部 | 标题 `✦ 能力决策`；自动触发时在模型徽标右侧显示 `自动` 徽标（`title="停顿 {pause}s 后自动发起"`）；模型徽标（已保存模型名）；关闭按钮禁用（见 §5.8） |
| 内容区 | 状态行 `正在评分… · 1 次请求 · {N} 个能力` + 6 行骨架（每行：勾选框占位 + 名称条 + 分数条占位） |
| 阈值行 | 显示但禁用（滑杆不可拖动，阈值数值保持；**不显示 `已选 n / N` 计数**） |
| 底栏 | 仅 `取消评分` 可点；`重新评分`、`应用所选` 不呈现（UX v1.5 §6.7） |
| 时长 | 不设硬超时上限（以宿主 / 请求超时为准）；超过 15 秒时在状态文案旁追加 `正在等待 Jev 服务…`（弱色，不重复弹窗） |
| 结果到达 | 状态行与骨架替换为结果列表；结果态**没有说明行**；焦点不强制移动（读屏通过 `aria-live="polite"` 播报 `评分完成，共 N 个能力`） |
| 取消 | 见 §5.8；自动触发被取消后同一草稿静默，直到草稿再次变化 |


### 5.6 结果面板结构与排序

**结构顺序（自上而下）**：头部 → 阈值行 → 提示行（无匹配时）→ 结果列表（滚动）→ 底栏。
**结果态不渲染说明行、隐私行与阈值提示**；加载态状态行见 §5.5。

| 元素 | 规格 |
|---|---|
| 头部标题 | `✦ 能力决策` |
| 模型徽标 | `Jev · {已保存模型名}`；模型名过长时省略并 `title` 全名；评分使用**已保存配置**，未保存的表单修改不生效 |
| 结果行 | 勾选框 + 类型徽标 + 名称 + 一句话描述（1 行截断，`title` 全量）+ 分数条 + 数值 +（`reason="no-answer"` 时）`未获得评分` 弱提示 +（不可切换时）原因。**不显示作用域标签** |
| 分数 | 显示 2 位小数（`0.82`）；数值与视觉条并存，颜色不是唯一信息载体；视觉条宽度 = 分数 × 100% |
| 空描述 | 显示 `—`（不渲染空白行高） |
| 阈值行 | 见 §5.7；计数 `已选 {n} / {N}` 位于阈值行（N = 参与评分的全部能力数，含不可切换项） |
| 提示行 | 仅无匹配时显示 `没有达到阈值 {t} 的能力，可调低阈值或手动勾选`；不是常驻说明行 |
| 底栏 | 右侧：`重新评分` → `取消` → `应用所选（{n}）`；计数不放在底栏 |

**排序规则（固定，用户不可改）**

1. 主序：分数**降序**（按未取整的原始分数比较；显示取 2 位小数，不参与比较）。
2. 同分（原始分数完全相等）：技能在 MCP 之前。
3. 仍同分：按名称升序（不区分大小写，使用 Unicode 码点顺序）。
4. 仍相同：按首屏能力列表的默认顺序（稳定排序兜底）。

- 不可切换能力**与其它能力一起参与排序**（它们同样有分数）；不单独分组到底部。
- `reason="no-answer"` 的能力按 `score=0` 参与排序（与正常 0 分相同），不丢弃、不置底特殊处理。
- 结果列表不支持按名称/类型重排；不提供“只看某类”筛选（本期）。
- 结果行不显示作用域标签（v1.2 裁决 P2，见 §5.3）。
- 自动触发与手动触发的结果面板结构一致，仅头部 `自动` 徽标不同（UX v1.5 §6.3）。


### 5.7 阈值与勾选语义

| 项 | 规格 |
|---|---|
| 控件 | 原生滑杆（range），`min=0`、`max=1`、`step=0.05`，默认 `0.50`；旁边显示当前值（2 位小数）；键盘 `←/→` 步进 0.05，`Home/End` 到 0 / 1 |
| 预勾选 | **分数 ≥ 阈值** 的可切换能力自动勾选（含等于）；`< 阈值` 不勾选 |
| 阈值与列表 | 调整阈值**不隐藏任何结果行、不改变排序、不重新请求**（原因：手改勾选需要看到全部行；“无匹配”用提示行表达，见下） |
| 手改优先 | 用户手动勾选/取消某行后，该行进入“手动覆盖”状态：**之后调整阈值不再改变该行**；其它未手改的行继续按阈值联动 |
| 重新评分 | 产生新结果集：手改状态全部清空、按新分数与当前阈值重新预勾选；**阈值数值保留当前值**（面板未关闭时） |
| 关闭后重开 | 视为新结果面板：阈值回到默认 0.50，手改清空 |
| 自动触发 | 自动触发打开面板时同样重置为默认 `0.50`；不继承上次手动调整值，也不因自动触发而改变已保存配置 |
| 计数 | `已选 {n} / {N}`：n = 当前勾选的**可切换**能力数（含手改）；N = 参与评分的能力总数（含不可切换项）；不可切换行不计入 n。**不使用可切换数 M 作分母** |
| 无匹配 | 若没有任何能力达到阈值 → 结果列表上方显示提示行 `没有达到阈值 {t} 的能力，可调低阈值或手动勾选`；列表仍展示，用户可手动勾选 |
| 全选 / 全不选 | 不提供“全选”按钮（避免误伤）；阈值 0 即等价全选可切换项（分数 ≥ 0 恒真） |
| 应用时 | 只应用**当前勾选**的可切换能力；不可切换行永远跳过 |

### 5.8 重新评分 / 取消 / 关闭 / 并发

| 动作 | 规格 |
|---|---|
| 重新评分 | 使用**最新草稿**重新发起一次评分（一次运行）；评分中禁用；若草稿为空 → 禁用 + tooltip `输入框已清空`；当前结果被替换（不做新旧对比） |
| 取消（结果态） | 关闭面板、回到打开前形态、丢弃结果、不改变任何开关 |
| 取消（评分态） | `取消评分` 中止本次评分（丢弃本次结果）；不弹确认。**若是自动触发**：同一草稿保持静默，需再累计编辑 ≥「最少修改间隔字符数」并停顿达标才可能再次自动触发；面板回入口态，可显示约 3s 弱提示 `已取消本次能力决策` |
| 关闭 `×` | 结果态 = 取消；评分态**禁用**（tooltip `评分中，取消请点「取消评分」`）；应用态禁用 |
| `Esc` | 结果态 = 取消；评分态不响应；应用态不响应；输入框内按 `Esc` 不清空草稿（沿用宿主行为） |
| 连续点击入口 | 点击后立刻进入评分态并禁用按钮；双击只产生一次评分请求（验收：请求计数 = 1） |
| 自动触发 ↔ 手动点击竞态 | 停顿到点与手动点击几乎同时发生 → 只发起一次评分（以先到者为准）；请求计数 = 1 |
| 停顿计时取消 | 停顿计时期间手动点击 → 立即触发；停顿计时期间草稿再次变化 → 重置计时并继续累计编辑字符数；停顿计时期间条件失效（切到 active / 关闭自动触发 / 草稿被清空 / 草稿字数或修改量跌破门槛 / 配置读取失败）→ 停止计时，不补触发 |
| 自动触发门槛 | 每次自动触发前校验：草稿字符数 ≥「最少触发字数」且自上次能力决策（自动或手动）以来编辑字符数 ≥「最少修改间隔字符数」；同一草稿（0 编辑）不会再次自动触发；手动点击不受门槛限制（但评分中按钮禁用） |
| 编辑计数重置 | 任意一次能力决策触发（自动或手动，成功发起评分即重置）、草稿被清空、发送首条消息后，编辑字符数归零；保存配置 / 切换 Tab / 开关自动触发不重置 |
| 结果态草稿变化 | 结果面板打开时草稿变化：不改变已显示结果，仅累计编辑字符数；若自动触发开启且字数 / 修改量门槛满足、停顿达阈值 → 以新草稿自动重新评分并替换为评分中态（UX v1.5 S19）；手动点「重新评分」则立即替换 |
| 自动触发关闭（默认状态） | 停止武装计时、不显示倒计时、不产生自动请求；已进行中的评分不受影响；手动按钮仍可用；不弹提示；入口显示 `自动触发默认关闭 · 可在 Jev 模型 Tab 开启` |
| 应用防抖 | 点击 `应用所选` 后按钮立即禁用并显示 `应用中…`；双击只执行一次应用 |
| 评分期间重评 | 「重新评分」在评分中禁用；若面板被关闭后旧请求返回，结果直接丢弃，不弹窗、不写入任何状态；不同评分运行之间以“最近一次”为准，不累加 |
| 多标签页 | 同一配置 / 会话可能在多个标签页操作：本期按“最后一次操作生效”处理，不提示冲突（O-11） |
| 应用成功后 | 面板关闭；本次决策已把编辑字符数重置为 0（自动 / 手动均重置）；未再累计到「最少修改间隔字符数」前不会再次自动触发 |

### 5.9 应用语义

**应用 = 以当前勾选为筛选结果，重写当前会话中全部可应用能力的开关状态；不改项目默认。**

| 项 | 规格 |
|---|---|
| 作用域 | 仅当前会话、内存态；与现有会话能力开关完全一致（技能：关闭 / 恢复；MCP：项目条目挂载、全局/外部实例按会话屏蔽或恢复） |
| 筛选语义 | 对当前会话全部**可应用**能力：**勾选 → 启用**、**未勾选 → 关闭**；只写当前状态与目标状态不一致的项 |
| 计数 | 成功支返回 `enabled`（本次实际启用数）、`disabled`（本次实际关闭数）、`applied = enabled + disabled`；状态已一致的项不写入、不计入计数 |
| 不可应用项 | `hard-disabled` / `not-restrictable` / live 下 `not-toggleable` 一律**不动**，不计入 enabled/disabled；结果行仍置灰 + 原因 |
| 已一致项（already-applied） | 目标状态已满足的项进 `skipped` 且 `reason="already-applied"`；客户端**不把它展示为「不可切换」跳过**，也不计入跳过提示；重复应用时可能 `enabled=0、disabled=0` |
| 会话未激活（冷会话） | 入队**完整目标 ops（含关闭项）**，chips 立即回显；提示 `已加入本会话，发送首条消息后生效（启用 {enabled} · 关闭 {disabled}）`；`agent/created` 后按 ops 重放 |
| 冷会话 + 跳过项合并 | 若同时存在真正不可应用项，合并为一条提示：`已加入本会话，发送首条消息后生效（启用 {enabled} · 关闭 {disabled}）；{k} 项不可切换已跳过`；**不弹两条提示** |
| 成功（会话已激活） | 关闭结果面板 → 回到**收起态能力条**（chips / 计数按筛选结果更新）→ 轻提示 `已应用：启用 {enabled} 项、关闭 {disabled} 项（仅当前会话）`；有真正不可应用跳过时追加 `；{k} 项不可切换已跳过` |
| 失败 | 停在结果面板，保留勾选与滚动位置；行内错误条 `应用失败：{reason}` + `重试`；**回滚**本次已提交的修改（启用与关闭均按前态逆序恢复）；若回滚也失败，错误条追加 `部分修改可能未回滚，请刷新页面或到能力面板确认` |
| 自动触发来源 | 应用成功后同样关闭面板；本次决策已把编辑字符数重置为 0（自动 / 手动均重置）；未再累计到「最少修改间隔字符数」前不会再次自动触发 |
| 应用成功后刷新页面 | 会话开关按现有语义回到项目默认（不持久化）；能力条 chips 随默认状态重新渲染 |

### 5.11 错误分类与文案（评分面）

| 分类 | 判定（产品语义） | 标题文案 | 说明文案 | 主 CTA | 次 CTA |
|---|---|---|---|---|---|
| `auth` | 鉴权失败（401/403） | `评分失败：API Key 无效或无权限` | `请到「Jev 模型」Tab 检查 API Key 或环境变量。` | `去配置` | `取消` |
| `model` | 模型名不可用 | `评分失败：模型 {model} 不可用` | `请检查「Jev 模型」Tab 的模型名。` | `去配置` | `取消` |
| `baseUrl` | Base URL 地址错误 / DNS 失败 | `评分失败：无法连接 Jev 服务` | `请检查 Base URL 与网络后重试。` | `重试` | `去配置` / `取消` |
| `network` | 网络错误 / 连接被拒 | `评分失败：无法连接 Jev 服务` | `请检查网络后重试；若使用代理，请确认宿主可访问。` | `重试` | `取消` |
| `timeout` | 请求超时 | `评分失败：请求超时` | `Jev 服务响应超时，请稍后重试。` | `重试` | `取消` |
| `rateLimit` | 429 | `评分失败：请求过于频繁` | `请稍后重试。` | `重试` | `取消` |
| `server` | 5xx | `评分失败：Jev 服务暂时不可用` | `这是服务端问题，请稍后重试。` | `重试` | `取消` |
| `context` | 上下文超限（含 `max_tokens_exceeded`） | `评分失败：输入内容超出模型上下文上限` | `请缩短输入框草稿后重试。` | `重试` | `取消` |
| `configMissing` | 请求时发现配置缺失 | `评分失败：尚未配置 Jev 模型` | `请先完成配置。` | `去配置` | `取消` |
| `configError` | 读取配置失败 | `读取 Jev 配置失败` | `请稍后重试，或到「Jev 模型」Tab 检查。` | `重试` | `去配置` / `取消` |
| `unknown` | 其它 | `评分失败：{reason}` | `请重试；若持续失败，请检查 Jev 配置。` | `重试` | `取消` |

- 所有错误原文必须中文可读；技术细节（HTTP 状态码、上游 message）并入 `{reason}` 或放在次要行，不显示裸栈。
- 错误文案中**不得包含 API Key、环境变量值或草稿全文**。
- 错误态不自动重试、不自动关闭；**自动触发失败后同一草稿不自动重试**，需用户手动重试或修改草稿后触发。
- **单能力缺分 / 非法分不进入错误态**：按 §5.4 容错为 `score=0` + `reason="no-answer"`，行显示「未获得评分」弱提示；只有整体失败（HTTP / 鉴权 / 超时 / 上下文 / 空能力等）才进入错误态。
- 不分片：不存在“分批失败 / 部分结果”类错误；一次运行要么整体成功、要么整体失败（容错不是部分失败，而是完整结果集中个别能力无答案）。
- HTTP 状态映射：401/403 → `auth`；404 → `model`（或 `baseUrl`，按客户端可辨识程度）；400/413/422 → `context`（内容/请求超限）；429 → `rateLimit`；529 与其它 5xx → `server`。

### 5.12 键盘与可访问性

| 项 | 要求 |
|---|---|
| 结果面板语义 | 非模态对话框语义（`role="dialog"`、`aria-modal="false"`、`aria-labelledby` 指向标题）；**不要求 `aria-describedby`**（说明行已移除，可为空/不设置）；打开后焦点移到面板标题容器（`tabindex="-1"`），读屏播报标题 + 状态；关闭后焦点回到触发按钮 |
| 状态播报 | 评分中 / 结果 / 错误 / 无匹配使用 `aria-live="polite"` 的状态节点；评分完成播报 `评分完成，共 {N} 个能力，已勾选 {n} 项` |
| 停顿计时播报 | 等待停顿的倒计时 / 进度提示不使用逐秒 `aria-live`（`aria-live="off"` 或静态文本），避免持续打断读屏；自动触发开始时播报一次 `停顿时长已达，已自动发起评分`（`auto.live.autoStart`），评分完成再播报 |
| 自动触发的焦点 | 面板自动展开时**不强制移动焦点**（用户可能在输入框继续输入）；读屏通过状态节点感知；用户可随时 `Esc` / 取消评分 |
| Tab 顺序 | 头部（关闭）→ 说明（不可聚焦）→ 阈值滑杆 → 结果行勾选框（逐行）→ `重新评分` → `取消` → `应用所选` |
| 滑杆 | 原生 range；`←/→` 0.05、`Home/End` 0/1、`PageUp/PageDown` 0.1；`aria-label="相关度阈值"`、`aria-valuetext="{0.50}"` |
| 结果行 | 勾选框是原生 checkbox；`aria-label="选择 {能力名}"`；不可切换时 `aria-disabled` + 原因进入 `aria-describedby`；行本身不可聚焦（避免双焦点） |
| 关闭 | `Esc` 结果态关闭；评分态不关闭（见 §5.8）；应用中不关闭 |
| 焦点环 | 所有可聚焦元素 `:focus-visible` 可见（沿用现有 2px 外环 + 1px 描边），不出现鼠标点击后的白色焦点竖条 |
| 颜色 | 分数、勾选、不可切换都不能只靠颜色表达（数值 + 文本 + aria） |
| 动效 | `prefers-reduced-motion: reduce` 时无骨架呼吸/进度动画；自动触发无弹跳/闪烁 |

- [ ] **AC-ENT-28（改配置立即生效）**：在配置页修改开关 / 停顿阈值 / 最少触发字数 / 最少修改间隔字符数并保存 → 返回首屏无需刷新，下一次草稿变化即按新值判定（分别覆盖开启→触发、关闭→不触发、字数门槛提高→不触发、修改量门槛提高→不触发）。
- [ ] **AC-ENT-29（编辑计数重置点）**：分别验证：①一次自动触发后计数归零（<4 编辑不再触发）；②一次手动触发后计数归零；③清空草稿后计数归零；④发送首条消息后 hero 卸载，计数丢弃；保存配置 / 切换 Tab 不重置计数。
- [ ] **AC-ENT-30（门槛与停顿计时独立）**：连续输入使停顿计时反复重置，但编辑字符数持续累计；最终停顿达阈值时，两门槛均满足才触发；若仅字数满足而修改量不足，则不触发且无请求。

### G. 状态、错误与防抖

- [ ] **AC-ERR-1（未配置）**：未配置时入口仍可点（蓝点）并引导到配置 Tab（同 AC-ENT-4），不出现评分请求，自动触发不武装。

- [ ] **AC-ERR-5（网络错误可重试）**：连接被拒 / 超时 → 对应分类文案 + `重试`；恢复正常后点 `重试` 成功出结果。

- [ ] **AC-ERR-7（内容过长）**：草稿超长或能力过多触发上下文错误 → `评分失败：输入内容超出模型上下文上限` + `请缩短输入框草稿后重试。`；**不自动截断、不分片**；缩短草稿后 `重试` 成功。
- [ ] **AC-ERR-8（容错不进入错误态）**：缺分 / 字符串 / 越界分数 → **不出现** `评分失败：评分结果不完整` 错误态；按 no-answer 规则展示完整列表并可应用；只有整体失败（401/超时/上下文/空能力等）才进入对应错误态。
- [ ] **AC-ERR-9（连续点击）**：快速双击（或连续点击 5 次）`✦ 能力决策` → 只发起一次评分运行；按钮在首击后立即禁用。
- [ ] **AC-ERR-10（竞态）**：评分中点击 `取消评分` 后旧结果返回 → 不弹窗、不恢复面板、不写入任何状态；再次触发得到全新结果。
- [ ] **AC-ERR-11（草稿变化）**：结果面板打开后修改草稿 → 已显示结果不变（无说明行提示）；点 `重新评分` 用新草稿请求（假端点请求体中的草稿为新值）；把草稿清空 → `重新评分` 禁用，tooltip `输入框已清空`。
- [ ] **AC-ERR-12（读取配置失败）**：点击 `✦ 能力决策` → 结果面板显示 `读取 Jev 配置失败：{reason}` + `重试` / `去配置`；恢复后重试成功。
- [ ] **AC-ERR-13（自动触发失败不自动重试）**：自动触发后假端点返回 401 → 错误态；保持同一草稿等待 10 秒 → 不产生新请求；手动点 `重试` 才发起 1 次；修改草稿并停顿后才可能再次自动触发。
- [ ] **AC-ERR-14（自动触发与输入并发）**：自动触发评分中继续输入 → 不打断当前请求、不发起新请求；评分结束后若草稿已变化，停顿满阈值才再次自动触发。
- [ ] **AC-ERR-15（停顿期间手动点击）**：停顿计时中点击按钮 → 立即触发，计时取消；假端点仅 1 次请求。
- [ ] **AC-ERR-16（等待期间条件失效）**：等待停顿期间切到 active 相位 / 关闭自动触发 / 清空草稿 / 配置变为不可读 → 停止计时，不补触发、不弹错误。
- [ ] **AC-ERR-17（旧外壳草稿读取降级）**：旧外壳无 `useInput` 时，入口保留；DOM 兜底可读 → 自动触发与手动触发均可用；DOM 兜底也失败 → 按钮禁用 + tooltip `无法读取输入框内容`，不自动触发。

### H. 安全与隐私

- [ ] **AC-SEC-1（密钥不出宿主）**：保存密钥后，浏览器 DevTools 的 Network 响应、DOM、LocalStorage / SessionStorage / IndexedDB 中均无密钥明文；界面只显示来源与末 4 位；插件 RPC 响应只包含“已配置 / 脱敏状态”。
- [ ] **AC-SEC-2（请求由宿主发起）**：评分与测试连接时，浏览器 Network 面板中只有插件自身 RPC 请求，没有对 Jev Base URL 的直接请求；假端点只看到来自宿主的请求。
- [ ] **AC-SEC-3（密钥不进入请求体与日志）**：假端点记录的请求体不含密钥；宿主控制台 / 插件错误文案不含密钥与环境变量值。
- [ ] **AC-SEC-4（环境变量模式）**：配置文件中只保存变量名（不保存变量值）；浏览器界面不显示变量值；未设置变量时给出明确错误而不是静默失败。
- [ ] **AC-SEC-5（隐私告知）**：配置页常驻安全/隐私说明（含草稿与能力名称 / 描述会发送到你配置的 Jev 服务）；结果面板不再展示隐私行；未配置前不会发起任何评分请求。
- [ ] **AC-SEC-6（发送范围）**：假端点请求体只包含草稿 + 能力名称/描述（以及宿主实现所需的指令），不包含历史消息、文件正文、路径、其它会话内容。

### I. 可访问性与键盘

## 7. 假设与风险

### 7.1 假设

| # | 假设 | 若不成立的后果 |
|---|---|---|
| A-1 | 首屏可以通过宿主槽 props 读取输入框当前草稿**并订阅其变化**（调研已给出 API 面，真机待验证）；停顿自动触发依赖该订阅 | 退化为 DOM 读取 + 输入事件（需清洗占位符）；两者都失败时入口禁用 + tooltip（§8 O-6） |
| A-2 | 一次评分请求可以覆盖全部可评分能力；上下文不足时**产品选择失败而非分片** | 若真实场景常超限，需评估能力上限或后续版本引入分片（本期明确不做） |
| A-3 | 模型能为每个能力返回一个可用于排序的 0–1 分，且能按能力标识一一对应 | 需要改评分设计（分组/两段式），可能推翻“一次请求”约束 |
| A-4 | 现有会话开关（技能 / MCP）语义不变，应用只写内存态、不落盘 | 若宿主语义变化，应用语义与回滚需重写 |
| A-5 | 首屏能力列表能提供技能 / MCP 的名称与一句话描述 | 若描述缺失，评分质量与列表可读性下降（显示 `—`） |
| A-6 | Jev 服务可从宿主网络访问（含代理/证书由宿主环境决定） | 连接类错误会常见；需在错误文案中给出网络排查方向 |
| A-7 | 配置保存后宿主能立即读到新配置（无需重启） | 与用户需求“保存后即生效”冲突，需架构补齐 |
| A-8 | 冷会话可以先记录会话选择、在会话激活后自动生效（按 Lead 裁决：chips 立即回显 + 首条消息后生效） | 若宿主不支持，需降级为会话激活后才能应用，并改写提示文案 |
| A-9 | 用户输入停顿 1.0s 是可感知且不会频繁误触的默认值 | 若误触频繁，用户可调高停顿阈值 / 字数 / 修改量，或直接关闭自动触发；默认值可在后续版本调整 |
| A-10 | 「输入停顿后自动评分」**默认关闭**，首次使用不会产生自动请求与意外成本 | 用户主动开启后才可能产生请求；若默认关闭导致功能发现性不足，入口提示与配置区说明需足够醒目 |
| A-11 | 默认门槛（停顿 1000ms / 最少触发字数 10 / 最少修改间隔 4）足以覆盖不同输入习惯 | 若不够，用户可在配置中调整；范围 300–3000ms、1–200、1–100 是精度与易用性的折中 |
| A-12 | 编辑字符数可用「最长公共前缀 / 后缀」对齐计算，覆盖键入、粘贴、删除、替换、撤销等常规输入 | 若输入法 / 撤销导致计数与实际感知偏差，需调整算法或放宽门槛；不得静默清零 |

### 7.2 风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R-1 | 首屏（冷会话）技能开关不可写，应用失败 | 核心场景不可用 | Lead 已裁决按 O-1「排队生效」口径；架构需落地 |

| R-3 | 中文草稿 + 英文能力描述的准确率 | 分数偏差 | 调研给出语言建议；阈值可调、允许手改兜底 |
| R-4 | 评分请求把内部能力描述发到第三方服务 | 隐私顾虑 | 配置页 / 结果面板常驻隐私说明；只发名称与描述，不发正文 |
| R-5 | 评分耗时超过用户耐心 | 放弃使用 | 加载态明确进度与“可用取消”；不阻塞输入框（面板可关闭） |

| R-7 | 与 UX 稿在「评分中是否允许关闭」等细节不一致 | 原型返工 | 已按 Lead 裁决统一（`×` 禁用 + `取消评分` 可中止）；UX v1.5 同步 |

| R-10 | 自动触发把“打字过程”变成请求：长对话 / 反复修改草稿会产生多次请求 | 成本与打扰 | **默认关闭**；开启后受停顿阈值 + 最少触发字数 + 最少修改间隔字符数三重约束；常驻成本提示；可随时关闭 |
| R-13 | 自动触发默认关闭导致新用户不知道有该能力 | 功能发现性下降 | 入口弱提示「自动触发默认关闭 · 可在 Jev 模型 Tab 开启」+ 配置区说明 + 原型/文案评审确认 |
| R-14 | 编辑字符数统计与用户直觉不一致（输入法组合、撤销、替换、跨行粘贴） | 自动触发过早 / 过晚 | 按最长公共前后缀对齐定义插入与删除；composition 结束才计数；验收用可编排编辑序列覆盖；门槛可调 |
| R-11 | 自动触发与输入法（拼音组合）干扰，组合期间误触发 | 中英文输入体验 | composition 期间不触发，`compositionend` 后起算 |
| R-12 | 旧外壳无法读取草稿，自动触发不可用 | 功能降级 | 保留入口 + DOM 兜底；都失败则禁用 + tooltip；文档写明最低外壳版本要求 |
